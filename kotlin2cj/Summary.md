**整体膨胀率仅 1.12 倍**，算法代码几乎零膨胀（×1.02）。膨胀主要来自：

- 部分 API 名称转换（如 `add()` → `append()`）

### 5.2 已知限制

通过测评发现以下 Kotlin 特性尚未支持（✅ 表示已在本轮实现）：

| 特性 | 状态 | 影响 | 优先级 |
|:---|:---:|:---|:---:|

| `while(true)` 返回推断 | ✅ 已支持 | 自动添加 `: Unit` 返回标注 + 不可达默认返回值 | P1 |
| companion object | ✅ 已支持 | 伴生对象成员渲染为 `static` 方法/属性 | P2 |
| 扩展函数 | ✅ 已支持 | `fun Type.name()` → `extend Type { func name() }` | P2 |
| 解构声明 | ✅ 已增强 | 多层嵌套解构与数据类解构 | P2 |

| 属性委托 | ❌ 不支持 | `by lazy` 等委托模式 | P3 |

### 5.3 Float 格式化差异

Cangjie 的 `Float64` 默认打印 6 位小数（如 `5.000000`），而 Kotlin 打印 `5.0`。翻译器正确处理数值语义，但输出格式需在预期结果中适配。此为**仓颉平台特性**，非翻译器缺陷。
